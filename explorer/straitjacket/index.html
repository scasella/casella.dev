02PrimerFor newcomers · about a minute

How a language model looks something up, in sixty seconds

Schematic

Four ideas are enough to follow everything on this page. Each one takes about fifteen seconds.

Where this picture breaks

These drawings are simplified. The model reads all the words at once. Layers also contain other parts (MLPs) that this page does not draw. Attention spreads across many words, and what a head copies is a list of numbers that only becomes the word “red” when it is read out at the top.

Under the hoodT2 §2.2, §3.1–3.2
  • Residual stream. The “column of numbers” is the residual stream at one token position. Each layer's attention heads and MLP read it and add their outputs back into it, and the last position's stream is read out into next-token logits.
  • QK and OV. A head's query–key (QK) circuit sets its attention pattern, where it looks; its output–value (OV) circuit sets what it writes back, what gets copied. The framing follows Elhage et al. 2021, A Mathematical Framework for Transformer Circuits, and Olsson et al. 2022, In-context Learning and Induction Heads.
  • GQA. Qwen3-0.6B's 16 query heads per layer share 8 key/value heads, so query head h uses KV head ⌊h/2⌋. d_h = 128, and the SwiGLU MLP width is 3,072. Because two query heads share each K/V head, head-level interventions at the final position T are applied as anchored float32 deltas on that one query head's output, without editing the shared K/V projections (T2 §2.2). So a “K” or “V” patch recomputes this head's attention at the last word with the donor's keys or values and changes only this head's output. The other query head on the same K/V head is left as it was.
  • Margin. m(x) = ℓ(x)·(logit_y0 − logit_y1), signed so that m > 0 when the model prefers the correct (bound) color. The effect of a patch is Δm = m_clean − m_patched, and Δm > 0 means it pushed toward the twin's answer. Direction % is the share of prompts with Δm > 0. It is neither accuracy nor a flip rate.
  • Points. One point (logit) of two-way lead multiplies the odds between the two words by e ≈ 2.7. This follows from softmax: the ratio of two words' probabilities is e raised to their logit difference; this page never turns a specific result into odds.

03SetupThe input · 2 × 2 × 2 = 8 versions

The test: a two-row table and three switches

Schematic prompt

v4 → v7 · families of 8 prompts · T2 §3.1–3.2

Every test is a tiny table. Two rows each pair a made-up key with a color, and then a question asks for one key's color. The team built prompts in families of eight by flipping three . Each flip changes the right answer, and each for a different reason. That is what lets you take the machine apart.

Switch A swaps the colors between the rows. Switch B asks about the other key. Switch C swaps which key sits in which row, and leaves the question word for word the same. Keep an eye on switch C. It produced this study's biggest surprise.

Under the hoodT2 §2.3, §3.1–3.2, §4.1–4.2, §7

What each switch keeps. Switches A and C keep the same multiset of tokens (the same tokens, rearranged), the length and the color positions (p1, p2); switch C also keeps the last 8 tokens. Under switch B every earlier context token is identical and only the asked-for key changes, so switch B makes no claim about keeping the same tokens.

Notation. A prompt is x = (k_order, c_order, q_key). Switch A is Axis A, the value-color swap (k_order, 1−c_order, q_key). Switch B is Axis B, the query swap (k_order, c_order, ¬q_key). Switch C is Axis C, the context-key swap under a fixed query (1−k_order, c_order, q_key). Each prompt has three matched opposite-answer donors inside its group of eight.

What each donor is used for. Axis A donors separate values from routing (A_ov_color, A_ov_other, A_qk). Axis B donors test the final query (B_q_final, and B_upstream_Q through the upstream heads). Axis C donors test keys against the query (C_k_color, C_q_final, C_ov_color, C_upstream_Q). Every effect is the drop in the signed margin, Δm = m_clean − m_patched, so Δm > 0 means the patch pushed toward the donor's answer. "Direction %" is the share of prompts with Δm > 0; it is not answer accuracy.

What each switch can rule out.

  • Switch A keeps the answer's position, so it isolates what the copiers carry (OV). A_qk should sit near 0 by design, as a signed median; single prompts can still move, and the effects cancel on average (v7 Primary / Vocabulary: +0.0050 / −0.0199 logits signed, 0.5150 / 0.2642 absolute). A tiny A_ov_other shows the copied value comes from the two color positions.
  • Switch B keeps every earlier context token, so B_k_context and B_ov_context must be exactly 0 by causality; that zero is a sanity check. It isolates the final query, but it cannot tell a copy of the question apart from a match already made against the table.
  • Switch C keeps the question and the color tokens, so a context-free copy of the question (the planted literal_query_only_control) scores 0.0 through the router heads. A nonzero C_upstream_Q shows the final query depends on the table, and C_q_final against C_k_color weighs the query against key stamps.

None of the three shows where the question is first compared with the keys.

Datasets per run (v4–v7).

  • Calibration: 8 groups, n=64, red/blue.
  • Primary: 16 groups, n=128, red/blue, split across templates H1 and H2.
  • Vocabulary: 8 groups, n=64, green/yellow, split across H1 and H2.

. An exact one-sided binomial test over group means. Floors: 2−16 = 1.5259×10−5 (16 groups) and 2−8 = 0.00390625 (8 groups). A p at its floor means every group mean moved the predicted way; it is the smallest value this test can give. A floor p is a statement about group means and says nothing about size. A row can sit at the floor while some single prompts move the other way (v7 A_ov_color on green/yellow: 78.13% direction, which is 50 of 64 prompts Arithmetic, with p at the 8-group floor). With 8 groups, a p ≤ .01 bar can be met only at the floor, so it requires every group mean to move the predicted way Arithmetic.

Keys. Fresh single-token words from a response-blind whitelist, with a new seed each run (v7: 64 keys, seed 20261023). "Key1" and "Key2" on this page are placeholders: the write-up never lists a real key word.

04The harnessTightened run by run, v1 → v8

Five locks on an AI scientist

In place · self-reported

Codex CLI runs the experiments · gpt-6-luna reviews them · one 24GB M4 Pro MacBook Pro (mps)

An AI coding agent, Codex CLI, ran the experiments. A second AI, gpt-6-luna, checked its work and looked for holes. Left unsupervised, an agent can take classic shortcuts: testing on the prompts it tuned on, dropping the prompts the model got wrong, nudging a pass mark after seeing the results, or rounding a number to tell a cleaner story. The harness blocks each one with code.

Try the first lock: change one character of a sealed rule and watch its fingerprint change completely.

v1 · sealed bar ≥ 90.0% (116/128) · scored 115/128

The locks held even when they cost the team a result. In the first run, the model itself had to score at least 90% before anything else counted. It scored 115 of 128, which is 89.84%, one prompt short. The harness refused to round up and marked the run inconclusive, even though the head under study passed every one of its own checks.

So what

Each finding below carries a chip that says how far it got through these locks. Confirmed: measured in the capstone (v7), the only run that passed every sealed test. Measured: a real number from a side test, or from a run that did not pass. Seen after the fact: the team looked once the results were in. Seven earlier runs missed at least one sealed bar, and each miss taught something (see the run history).

Where this picture breaks

A lock here is a check written in code. The harness is cheat-resistant: it blocks the shortcuts listed. It cannot stop someone from choosing a new run's bars with knowledge of earlier, retired runs. All of it is self-reported, and the repository is not public yet.

Under the hoodT1 P1 · T2 §2.1–2.4, App A

Why build this? In October 2026, an essay by Nick Cammarata, "Neural Networks Are Already Clean", argued that neural networks are more legible than many assumed and that automated AI scientists could speed up interpretability research. Other researchers pushed back, calling for rigorous evaluation and for explanations of whole circuits (MIT Technology Review, Oct 19, 2026). This project tried the automated approach under strict, sealed rules.

Lock 1 · sealed plan (H01). manifest.json records SHA-256 digests of source modules, tests, lockfiles, prompt strings, token-ID arrays, donor indices, frozen head coordinates and comparators before the first target forward pass. v7 manifest: data/bounded-poc-v7-capstone/manifest.json, SHA-256 a59566919a93607e7eff114aa4342807978294ce2b75577cd097fbb55ab9a899, pre-inference commit ff46c4b. This is hash-locked pre-registration (SHA-256 fingerprints committed before inference). It gives tamper-evidence; it keeps nothing secret, and the write-up describes no third-party timestamp.

The demo. The box is hashed as UTF-8 with the browser's built-in SHA-256. The demo rule is v1's base-accuracy prerequisite; the capstone's Gate 0 bar was ≥ 80.0% on every split. Precomputed fallbacks: the 90.0% rule gives b24c6268…60e1 and the 89.8% rule gives 7ff57e8e…3e01; 60 of 64 characters differ.

Lock 2 · retired test sets (H02). Once a held-out split is evaluated or inspected, its files join a protected inventory checked before and after every later run: 1,053 protected files by the capstone (v7) and 1,416 after v8-repair. New keys come from a response-blind whitelist with a fresh seed: 20261023 (v7) and 20261024 (v8).

Lock 3 · planted models (H03). Five executable synthetic models in float64:

  • planted_pointer_model (the right mechanism): must pass every gate.
  • literal_query_only_control (copies the literal question word into the final query, without resolving which row holds it): must fail Subgate 2C.
  • direct_k_color_only_control (stamps keys onto the answer words, with no pointer in the query): must fail Gate 1C and Subgate 2C.
  • nuisance_control and reversed_control: must fail.

Lock 4 · two runs, one separate audit (H04, H05).

  • Two fresh OS processes; bfloat16 weights; float32 deltas; a single FIFO MPSBatchWorker; batch ≤ 64. 71 file pairs (655 arrays) were bit-identical in v5–v7.
  • Anchored delta: Hpatched = BF16(Hmeas,clean + [H̃rec,patched − Hrec,clean]FP32). Fused BF16 attention and explicit FP32 reconstruction differ by ≤ 0.045, and the self-patch identity error is 0.00000000.
  • Two-process bit-identity establishes "deterministic computational repeatability on frozen datasets"; generalization across datasets comes from the four disjoint key pools and template variations (T2 §7).
  • The audit imports no production grading functions and runs no PyTorch. It recomputes the attention probabilities (after position encoding), masked value deltas, group sign tests and gate booleans, with agreement ≤ 1.53×10−5 against a 3.0×10−5 tolerance.
  • Tests: 103 unit tests and 66 Metal hardware regressions passed (manuscript, App A).

Lock 5 · reference-bound review (M03, M04). In v4-confirm, 55 of 56 floating-point claims matched the saved arrays; one drifted by 4.88×10−13 (0.03109455108691406 vs 0.03109455108642578). From v5 on, the reviewer picks metric keys (metric_refs) and code binds the float64 values, giving 83/83 in v7. Narrative interpretation stays advisory. In the gold/silver run the reviewer read a table showing that "zeroing 19:5 resulted in 0 errors rescued" as evidence that 19:5 was not helping; the inversion was caught during adjudication.

The first run's bar (M05). v1 sealed a global prerequisite of unassisted ≥ 90.0% (116/128). The model scored 115/128 (89.84375%), so the verdict was INCONCLUSIVE, even though 19:5 passed every head-level gate (read-out 126/128, 98.4375%). Bars differed between runs: v4 was rejected partly at 88.3% / 85.9% against 90%, and the capstone's Gate 0 required ≥ 80.0% on every split.

Limits. Cheat-resistant: it blocks the shortcuts listed. Bars for a new run can still be chosen with knowledge of retired runs. Everything here is self-reported, and none of the code is public yet.

Two later heads, 21:13 and 22:9, do the same job. Three heads lower down, in layers 15 to 17, supply the that tells these copiers which row to read.

The pointer is worked out before the copiers look

Measured · v4 diagnosticConfirmed · v7

The AI reviewer's objection

“This is not a full proof of an abstract key-matching algorithm: under Axis B, the queried key changes, so an upstream head at the final token (17:1, 16:4, 15:4) can merely convey literal query identity ("Key1" vs. "Key2"), while actual key-matching happens against context keys stamped onto Kcolor at the color positions.”
gpt-6-luna, the project's AI reviewer

Put simply: maybe the router heads just repeat the question, “you asked for Key1”, and the matching happens later, against labels stamped on the answer words. Switch B cannot tell these two stories apart, because it changes the question itself. The reviewer was right.

So the team flipped switch C. The question stays word for word the same, and the colors stay where they were. Only the two keys trade rows, so Key1 now sits next to blue.

If the router heads only repeated the question, their signal would be identical in both versions, and transplanting it would change nothing. Transplanting only the routers' signal moved the model's preference the predicted way on 128 of 128 prompts. By the last word, three heads in layers 15 to 17 already carry most of the which-row-matched signal. This page calls that signal the .

So what

Where this picture breaks

“Pointer” is this page's word for the signal. The study shows pointer-like routing on two-row prompts, which falls short of showing that the model stores a literal row number. Key stamps still carried a minority share, about 17% in the first test.

Scope: what this does not show

  1. Pointer-like routing on two-row prompts. It does not prove that the model stores discrete symbolic slot variables.
  2. A verified, high-leverage causal subgraph, not an exhaustive or exclusive circuit. The earlier heads that first compare the question with the keys were not identified.
  3. Intervention ratios represent controlled contrast magnitudes rather than percentages of total causal mediation.
  4. Two-token next-token logit preferences on synthetic 2- to 4-record prompts in Qwen/Qwen3-0.6B. The confirmed circuit was tested on 2-record prompts. Unconstrained natural-text generation is not covered.
  5. One model and one checkpoint. Other sizes and families are untested.
  6. Every result here is the project's own report. The repository is not public yet, and nothing has been peer reviewed.

Ask a small AI for Key1 and you can now point to where the answer comes from: three heads in layers 15 to 17 carry a where-to-look signal, and three heads in layers 19 to 22 fetch the word. You can also point to where it goes wrong: a later head that leaned toward one word in one test, and a copier that drifts toward the last row. An AI scientist found all of it, and rules it could not bend checked it.

Key1 stands in for a real single-token key word.

Glossary, sources and colophon

Every term this page uses, where its numbers come from, and the machine it all ran on.

Glossary

25 terms · plain sentence, then the technical line

Any dotted-underlined word on the page opens its entry from this list.

Token
A word or piece of a word. The model reads a prompt as a row of tokens. The keys in this study are single-token words.
Layer
One of the model's 28 processing stages, stacked from layer 0 at the bottom to layer 27 at the top. Transformer blocks 0–27, each with attention and a SwiGLU MLP of width 3,072.
Attention head
A small unit inside a layer that looks back at earlier words and copies information from them. Each layer has 16, so the model has 448. 16 query heads per layer share 8 key/value heads (GQA: query head h uses KV head ⌊h/2⌋); head size 128.
Head name (19:5)
“19:5” means layer 19, head 5, counting from 0. layer:head, 0-indexed.
Query, key, value
A head at the last word sends out a query, compares it with a key on every earlier word, and copies the values of the best matches. The query and keys decide where to look; the values decide what gets copied. Attn(Q_T, K_1..T, V_1..T). QK sets the attention pattern; OV writes the output (Elhage et al., 2021).
Pointer
This page's word for the where-to-look signal the router heads write into the last word's query. A context-resolved routing signal in Q_final. Pointer-like; not shown to be a symbolic slot variable.
Points (logits)
The model's raw score for a possible next word. On this page, “points” means logits. One logit of lead multiplies the two-way odds by about 2.7 (e¹).
Margin
How far the right color's score leads the wrong color's score, in points. m(x) = ℓ(x)·(logit_y0 − logit_y1), positive when the model prefers the bound color.
Transplant test (patching)
Copy one internal signal from a twin prompt into the original run, change nothing else, and see whether the answer moves. Activation patching. Effect Δm = m_clean − m_patched; Δm > 0 is a push toward the twin's answer.
Twin prompt
A version of the prompt that differs in one controlled way and has the opposite right answer. The counterfactual donor, from the same 8-prompt factorial group.
Direction
The share of prompts where a transplant pushed the preference the predicted way. It counts direction only. Size and flipped answers are separate questions. Share of prompts with Δm > 0.
Switches A, B, C
Three ways to change a prompt: A swaps the colors, B asks about the other key, C swaps which key sits in which row while the question stays the same. Axes A, B and C of the 2×2×2 factorial: c_order, q_key, k_order.
Held-out prompts
Test prompts kept aside and never used to choose anything. Primary (n=128) and Vocabulary (n=64) splits.
Calibration prompts
A small set of prompts used to check or tune settings before the real test. n=64 per run.
Pre-registration (sealing)
Writing down the plan, the test prompts and the pass marks before running the experiment, so they cannot change after the results are seen. SHA-256 manifest.json frozen before the first target forward pass, plus a pre-inference git commit.
SHA-256 fingerprint
A fingerprint of a file or text. Change one character and the fingerprint changes completely. A cryptographic hash. It shows a file is unchanged since it was recorded; it keeps nothing secret.
Bit-identical
Two separate runs saved exactly the same numbers, down to the last bit. 655 of 655 .npz arrays equal across two fresh OS processes (v5–v7).
Sign test and p-value floor
A check that counts how many independent groups of prompts moved the predicted way. With 16 groups the smallest possible p-value is about 0.000015, which means every group agreed. Exact one-sided binomial sign test over group means; floors 2⁻¹⁶ (16 groups) and 2⁻⁸ ≈ 0.0039 (8 groups).
Ablation
Switching a part off (zero ablation) or replacing its output with its average (mean ablation) to see what changes. Mean ablation leaves a constant offset in place.
Steering (amplification)
Turning a part's output up or down to push the model's behavior. Centered amplification x + (α − 1)(x − μ).
Recency pull
A pull toward the most recent item, here the last row of a table.
Residual stream
The running list of numbers for each word. Every layer reads it and adds to it.
Logit lens
Reading the model's running guess partway up the layers, before it has finished.
Coalition
Heads that do the same job together. On this page: the three copiers 19:5, 21:13 and 22:9.
Bookkeeping (conservation)
If a head's output depends only on its query, keys and values, an effect missing from two of them must sit in the third. Conservation over Attn(Q_T, K, V). It assumes the parts add, which softmax and normalization need not respect, so the page calls it a prediction.
